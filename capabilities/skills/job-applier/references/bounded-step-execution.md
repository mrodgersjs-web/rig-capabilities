# Bounded step execution and context recovery

Run one leaf step per Aside session. The coordinator passes the exact leaf path/version, stable job/step/revision IDs, current task/session IDs, source/artifact paths and SHA-256 hashes, last checkpoint, holds and the bounded done-test. Do not preload the whole family, full transcript, all career evidence or all prior provider responses. Load the next leaf in its own session after the current checkpoint is saved.

Default context budget: at most 8,000 tokens in the selected source pack and at most 1,500 characters in each tool response shown to the model. Use the actual tokenizer when available; otherwise use a conservative estimate and label it. Ask tools for explicit JSON fields, projected rows and bounded ranges rather than printing raw large Jev receipts, evidence banks, repository inventories or document XML. Persist complete originals locally and keep their paths/hashes. A truncated excerpt must remain labeled partial; it cannot stand in for omitted source coverage or a full image review.

Select source evidence by the current leaf and requirement IDs. Read larger inputs in bounded projections with durable coverage tracking. If complete required evidence cannot fit, checkpoint and divide the current leaf into bounded subpasses in fresh sessions; retain one logical step identity and require complete combined coverage before its gate passes. Never silently drop referenced evidence, reduce the persona or invent facts to fit the window.

Before dispatch, set a finite done-test, elapsed-time budget and attempt cap. Default to one execution pass and at most two correction passes for a leaf revision, with a 15-minute active-work budget per session. Human waits are durable holds outside that active-work budget. At the cap, save current artifacts, exact errors, remaining holds and the next safe action, then stop and report. No repeating unchanged research, restarting the same search or rescoring unchanged content until a provider returns PASS. A correction pass needs a recorded material input change or newly available evidence.

Treat context-limit, token-limit and failed-compaction errors as nonretryable for the existing Aside session. Do not resend the same oversized payload or ask that session to compact again. Record the failure and current task ID; reconcile whether a dispatched action already completed. Start a fresh Aside session for the same logical step only after recovering the durable checkpoint, current artifact hashes and existing-operation state. Pass the compact checkpoint package, not the old conversation. Preserve original receipts and approvals; changed artifacts invalidate dependent approvals exactly as before.

A fresh session does not reset the logical step's attempt counter or bypass an uncertain external action. Carry the attempt history and submission_unknown state forward. No automatic ATS submit retry follows context recovery. If no valid checkpoint exists, report that blocker and reconstruct only the minimum source-bound step state without claiming prior completion.

Keep private GitHub evidence local and sanitized in external payloads. Existing red UNCONFIRMED review, Word fidelity, full persona, Jev/image holds, authenticated factual/page review and separate specific submission approval remain mandatory. These are skill execution instructions; installation and passing structural tests do not prove Aside enforces context limits at runtime.
