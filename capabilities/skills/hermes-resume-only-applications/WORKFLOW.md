# Execution workflow

1. **Preflight.** Run this package's verify_sources.py. Read sources.json and the selected DOCX locally (ZIP/XML extraction is sufficient). Read only relevant answer-bank fields. Record selected source hash and role lane. If the source changed, report the actual path and re-extract it before use; don't keep stale claims. Check the current repo guard before packet writes.
2. **Select targets.** Use supplied jobs or the existing ApplyOps queue, read-only. `scripts/apply_ops.py next --help` reveals current supported options; don't assume legacy flags. Check exact employer, job ID, location, live application URL and prior application ledger. Capture the current description from the official employer/ATS page. A closed, duplicate or unavailable listing does not become a made-up opportunity.
3. **Ground facts.** Build resume_facts.json with the selected path/hash, exact employer/title/date headings and source quotes. Keep clients, vendors, portfolio projects, university and military sections distinct. Grouped dates remain grouped. Ambiguous date/month/alias fields are unresolved. Document personal facts separately, using the current user instruction or dated answer-bank entry. No sensitive attributes inferred from names or military history.
4. **Assess and draft.** Map job requirements to supported/partial/missing evidence. A missing mandatory qualification is visible. Use the resume-writing skill for emphasis; use the packet-builder format for the dossier when useful. Company/role research supports statements about the job, not about the candidate. Keep cover notes concise and obey any portal character limit. Preserve the original DOCX; produce a separate variant only when needed.
5. **Answer precisely.** Record question text, question category, exact answer, source quote/reference, status and any ambiguity. Direct employment at an absent employer = No based on Mike's complete-history statement. A supported direct match = Yes. Never flatten current employment, employment by affiliates, contractor service, referrals, relatives, prior applications, work authorization or EEO into the same question. Known saved facts prevail over an indiscriminate No. Unsupported fields stay NEEDS_MIKE. Do not overwrite account-wide saved answers with a job-specific guess.
6. **Verify packet.** Rehash the actual attached resume; compare every career claim to its source passage. Explicitly inspect employer headings versus client names. Verify the target company never became a past employer. Check years/months, grouped roles, word limits, missing questions, duplicate history and attachment filename. Package verification is a review aid, not a legal or employment certification. A wording score does not prove truth.
7. **Prefill when requested.** Run `bsk doctor`; any FAIL means don't use that route. If healthy, `bsk session start`, use only its owned session, snapshot before actions and after navigation, and stop the session on success/error. Never stop another agent's browser session. Read and fill one field at a time from the verified answers, re-read selected options, confirm uploads, and stop before Submit. Do not bypass CAPTCHA, login or attestations. The legacy ApplyOps prefill adapter may use old packet/profile overrides: don't call batch-prefill blindly; review its inputs first.
8. **Record outcome.** Save a private ledger entry with employer/job ID/URL, source and attachment hashes, exact state, timestamp, missing fields and proof reference. Use confirmed submission receipts when available. An ambiguous post-submit timeout requires reconciliation, never an automatic retry. Report prepared and applied totals separately. Reuse the existing application-status system only through its verified interface; don't overwrite its history or invent a parallel source of truth.

## Packet contract

Create a new dated target directory under the registered cockpit's `luca/job-search/apply-ops/packets/` without overwriting an existing packet. Files: job_source.json, resume_facts.json, personal_facts_used.json, fit_matrix.json, tailored_resume (only if needed), cover_note.md, dossier.md (if needed), screening_answers.json, review_checklist.md, verification.json, proofpacket.json. Store only necessary private data. Evidence records include their source, timestamp, hash and status.

## Realistic completion

Workflow installed = files and dependencies verified. Packet prepared = actual files reviewed. Browser prefilled = actual fields/attachment verified. Applied = employer receipt or explicitly labelled user-reported completion. These are different results. This setup alone proves no successful application or browser submission.
