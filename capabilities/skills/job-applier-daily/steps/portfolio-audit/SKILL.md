# Portfolio audit

## Inputs
Current atomic requirements, existing authenticated repository read access and prior evidence index if present.

## Actions
Enumerate accessible repositories with pagination and actual account/scope evidence; retain partial access honestly. For JD-relevant repositories inspect immutable HEAD paths, substantive implementation, configuration and tests. Record original/fork/template status and upstream context. Classify implemented/prototype/documentation/teaser/unknown. Keep tests inspected separate from executed; this step runs no repository code. Separate repository mechanism, Mike's personal contribution and business outcome.

## Outputs
Portfolio audit with scope/time, repository visibility, immutable SHA/path citations, requirement IDs, mechanism classification, test status, personal contribution state, outcome state and missing evidence.

## Gates
Account ownership, imported forks, README promises and test file presence never prove personal authorship, production scale or test execution. Private source stays local; only safe supported descriptions enter hosted review or employer documents.

## Recovery
Recheck relevant HEAD and accessible scope on a new revision. Preserve historical audits; disclose incomplete access. Ask only contribution/result questions not answerable from available evidence. Do not change credentials or repository visibility.
