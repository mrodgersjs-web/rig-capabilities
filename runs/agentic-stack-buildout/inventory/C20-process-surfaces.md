## Gaps

- The listener inventory is intentionally bounded by `head -60`. Any LISTEN record after line 60 is absent from this artifact. For example, PID 6439 arguments name Temporal ports 7233/8233, but only the `127.0.0.1:49383` lsof record occurred inside the captured first-60 window; 7233/8233 are therefore not asserted as observed LISTEN sockets here.
- A LISTEN socket or sleeping process proves point-in-time liveness only. It does not prove health, request success, durable state, restart recovery, owner authority, retention, RPO/RTO, or suitability for a new workload.
- `pgrep -fl` is a full-command substring search. The large `hermes`, `node`, `python`, `worker`, Kestra, and Prefect match sets include helpers, clients, GUI subprocesses, and commands whose arguments merely contain the token. Counts are search-result counts, not counts of homogeneous daemons. Two Hermes matches exited between `pgrep` and `ps` and are recorded `ABSENT`, demonstrating snapshot race.
- The Ollama snapshot contained one `ollama` process and one Python guard-shaped match. The latter is not classified as a second Ollama server without a listener/command-specific receipt.
- Both Docker Desktop backend processes and Colima/Lima processes were present while `docker ps` returned 27 names. The active Docker CLI context and which daemon owns those 27 containers were not queried, so that association is `UNRESOLVED`.
- `docker ps` proves container state `running`, not container health, restart policy, volume durability, scheduler ownership, or recovery behavior. No `docker inspect`, health endpoint, or restart demonstration was run.
- The 36 Kestra `pgrep` matches were Docker client processes for MCP use; they do not independently prove 36 Kestra schedulers. The separate Docker row proves one running container named `kestra`, but its health/version/job state is `UNRESOLVED`.
- Most Prefect matches are MCP servers; only command-shape evidence distinguishes the listed worker-like PIDs. No Prefect API, pool, queue, heartbeat, or flow-run status was opened, so worker readiness is `UNRESOLVED` beyond process presence.
- OMP version and both candidate skill roots exist, but which root is native, preferred, or actively scanned remains `UNRESOLVED`; directory existence is not a load receipt.
- Hermes profile rows prove names/directories only. Their contents, startup wiring, enabled state, and active use were intentionally not read.
- A launchd plist filename proves installation only. `launchctl print` rc 0 proves a current service definition, and a PID proves current running state; neither alone proves a separately enabled override. Labels without a `keepalive` marker are listed as worker/watchdog mechanisms by name and state only, not asserted to respawn.
- Apple-owned listeners in the captured window (`rapportd`, `ARDAgent`, `ControlCenter`) were intentionally excluded from the non-Apple owner map. Their omission is by scope, not evidence that the ports are absent.
- Except for OMP, component versions were not requested by the allowed probes and remain `UNRESOLVED`. Process arguments were not used as credential evidence; secret values and environment values are absent from this artifact.
