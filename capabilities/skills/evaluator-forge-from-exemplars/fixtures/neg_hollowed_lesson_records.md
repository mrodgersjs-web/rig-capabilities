# experience-lesson-records — reference

This is the lessons-record exemplar with its load-bearing specifics removed.

> A lesson is a typed, evidence-bearing rule that fires as a gate on condition
> match. At run close the reflection step distills the trajectory into a record
> stored under a retrieval key. On a later task whose text matches the trigger,
> the mandated check becomes something the run must carry. The validator
> enforces every clause; the planted fixtures are permanent regression cases.

## What good looks like

The load-bearing seed from the source's own done-test — a lesson that must
fire, not merely be remembered. Good lesson records have all the required
fields and the evidence that earned them, and a run that matches the lesson
pays for it with a receipt.

## The done-test forms

Some fixtures are GREEN and some fixtures are RED. The exit-code fixtures are
the regression suite: each is the failure the gate exists to catch, kept so a
future edit that stops the gate biting turns a green red immediately.

## Why it is not a diary

The delta: a free-text improvements log with no condition key and no retrieval
path means a lesson is re-read by a human or never applied. Here the trigger is
a match key and the mandated check is a receipt the run must produce — the
lesson fires rather than being recalled.
