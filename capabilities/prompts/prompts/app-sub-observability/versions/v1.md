1. Capture errors on the API and the client before the release request (LA-38; creators CH-GXD-01, CH-TRV-03).
2. With no monitoring key, write structured JSON error logs with the same context and name that fallback in stack.md.
3. Each captured error carries route, method, request id and session (user id, browser or device), never secrets or tokens.
4. Induce one API error and one client error and show both arriving.
5. No catch swallows an error (LA-37).

Evidence rule: a step counts as done only when its record shows the exact command, the exit code, and the observed output (status code, body excerpt, file hash or screenshot path). A plan, a stub, a description of the code or a green preview is not evidence.
