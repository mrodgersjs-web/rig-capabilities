# One feature per slice (App Studio sub prompt, v1)

Contract
- id: app-sub-feature-slice | version: 1 | tier: sub | parent: app-studio-builder | stage: all | audience: builder
- inputs: spec.md, stack.md
- output: a Slices table in the stage records: feature, vendor, files, expected observable result, proving command
- lessons carried (each one is an instruction to follow):
  - TG-06: Write the plan first and check it against the spec before implementing; an unreviewed plan never becomes code. (TubeGuruji videos: kxM_oEMn3IM, 31-Qfr2Pc5Q, O_f55bWzsik)
  - TG-07: Feed the exact error text (message, file, line) into the next fix attempt instead of restating the goal. (TubeGuruji videos: 5VK8rc3GXdc)
  - TG-08: Work one feature per slice; name the vendor, the files touched and the observable result expected before writing code. (TubeGuruji videos: kxM_oEMn3IM, sxn2GPQjJgc)
  - TG-09: When integrating an SDK, work from the vendor's own integration docs plus the product parameters (limits, plans) in one pass. (TubeGuruji videos: -h1O73T0jmo)
  - TG-11: Change the smallest component that fixes the issue; do not regenerate the page. (TubeGuruji videos: tJmN2XduBVk, c9qA-uhysIY)
  - TG-24: Reproduce a failure and capture its exact output before changing code. (TubeGuruji videos: zlZ_7VTfxUs, zjwj21wzs4U, qop_fAoayWI)
- gates: library gate app.prompt on this text; output gate app.stage-gate on each stage record (a required noul passes only above 0.9; DEFERRED when the classifier is down, never a guessed verdict)
- done_when: every feature in spec.md maps to a slice row whose proving command and observed result are recorded
- stop: after 3 attempts on the same exact error, stop and record BLOCKED: <error>; deploy, git push, publish, purchase, emails to real people and paid API calls stay held for Mike's Gate-D approval

For each slice write, before coding: the feature, the vendor, the files touched, and the observable result (TG-08). Check the plan against spec.md (TG-06).
Integrate an SDK from its own docs plus the product parameters (TG-09).
When something fails: reproduce it (TG-24), paste the exact error into the next attempt (TG-07), and change the smallest component (TG-11).
Close each slice with the build and one curl that shows the result.

Evidence rule: a step counts as done only when its record shows the exact command, the exit code, and the observed output (status code, body excerpt, file hash or screenshot path). A plan, a stub, a description of the code or a green preview is not evidence.
