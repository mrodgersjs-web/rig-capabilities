# Headline and keyword extraction

The headline is both the stranger's two-second read and a search field. A bare job title wastes the space; almost nobody does more, which is exactly why doing more puts Mike ahead [headline-formulas, creator claim].

## The formula (RIG default)

`job title` + `a short clause naming who you help and the help itself` [headline-formulas].

- "marketing manager" becomes "marketing manager helping B2B SaaS companies close big deals" (the creator's own example).
- Lane B: the value clause is where the governance positioning goes, e.g. title + helping named buyers install governed AI that produces a measurable outcome. Offer-shaped claim only: "helping X do Y" is a claim about the offer; a results number is a claim about outcomes and belongs in the body with a source [headline-formulas].
- Job lane: the same structure serves a recruiter search instead (target role + domain + differentiator). The two headlines are different artifacts for different audiences; never average them into one line [headline-formulas].

## The two readers and where they conflict

- **The stranger** decides in about two seconds, after the photo, whether the rest is worth opening. Natural voice first.
- **The searcher** types a phrase. If the keywords are missing, a beautiful profile is never found [headline-formulas].
- Resolve toward the stranger: keyword density must never turn the line into a search string [headline-formulas].

## Conflict logged: the third-party variant

The profile-optimizer pack (third-party) prescribes a different headline: three options, each capped near 50 characters, sentence case, value-first, explicitly no job titles [profile-optimizer]. RIG keeps the title-plus-value formula as the default because it is the doctrine the rest of this stage and the classifier sync are built around; the short variant is offered when Mike asks for profile-optimizer by name (the router says that pack runs only on request) [viral-core]. Both agree on one thing: no fluff words.

## Keyword extraction (the cheap deterministic step)

1. Find 10 real targets: profiles of people in the role Mike wants, or postings for it.
2. Ask what the most common skills and keywords across those 10 examples are. This is the only AI workflow the source doctrine prescribes for profiles, and RIG has the corpus to run it better [headline-formulas].
3. Weave the set naturally into headline, About, Skills, and the custom button label. "Naturally" is the constraint: a keyword-stuffed About reads as a search string and fails the stranger [headline-formulas, about-and-featured].
4. The same extraction tells you which skills to attach to the profile [headline-formulas].

## Claim rules

- No metric of any kind in a headline unless RIG measured it [headline-formulas].
- Mike's current headline carries claims like "$4B M&A" and "100+ AI agents in production". Every such figure must survive "who measured that and what did they look at" before it stays [profile-audit].
- No invented numbers, clients, or quotes anywhere in profile copy [viral-core].
