# rig-lattice-system — reference

Canonical asset `rig-lattice-system` (skill). Path:
`capabilities/skills/rig-lattice-system`.

> Coordinate the work before you build it. A unit of work resolves to one
> canonical cell id and one BMS band **before** the first edit; the artifact
> leaves with a 40-engine verdict. The Z-axis is BMS confidence — IQRSQPI is
> the seven-step process that runs *inside* a coordinate, not an axis of it.

## What good looks like

The geometry is a number the CLI prints, not a claim in a doc:

```
$ bin/rig-lattice lattice summary --json
{"levels":7,"diamonds":3,"bms_modes":4,"steps":7,
 "primary":84,"cells":588,"archetypes":28,"version":"3.0"}
```

Three dialects, one canonical answer — the fusion's whole point, since four
repos had each invented their own spelling:

```
$ bin/rig-lattice lattice cell L1-1-A1-I1                    # bare-digit
$ bin/rig-lattice lattice cell L1-D1-A1-I1                   # canonical
$ bin/rig-lattice lattice cell intent.D1_physical.A1.intent  # dotted
→ all three: L1-D1-A1-I1  archetype A1.1  fallback A3.A1.1
             deterministic true  model_in_decision_path false  cost_band $0.001
```

The rejected shape names what is wrong with it rather than silently guessing:

```
$ bin/rig-lattice lattice cell L2-D1-Intent
error: Invalid cell_id 'L2-D1-Intent'. Accepted shapes:
  canonical  L{1-7}-D{1-3}-A{1-4}-{I1|Q1|R|S|Q2|P|I2}
  bare-digit L{1-7}-{1-3}-A{1-4}-{step}
  dotted     <head>.D{1-3}_<plane>.A{1-4}.<step>
This is the pre-Z-axis shape (no BMS mode). The Z-axis is BMS confidence,
not IQRSQPI — add the A{1-4} segment.                      # exit 2
```

## The band is derived, not chosen

```
raw   = failure_cost*0.4 + reversibility*0.3 + mechanism_clarity*0.3
final = clamp(raw - past_failure_rate*0.2 + (data_volume-0.5)*0.1
                  + ALTITUDE_BONUS[level], 0, 1)
```

Same criteria, two altitudes, two bands — the altitude term spans exactly 0.70
between L1 (+0.35) and L7 (−0.35):

| call | confidence | mode | budget | approval |
|---|---|---|---|---|
| `--failure-cost .9 --reversibility .8 --mechanism-clarity .9 --level L1` | 1.000 | **A1** | $0.00 | no |
| the same three criteria at `--level L7` | 0.520 | **A2** | $0.10 | no |

L1 mechanical work earns determinism; L7 doctrine work is pushed toward the
agentic bands by the same formula, with no human deciding it felt hard.

## The claim that had to be proven, not asserted

rig-capabilities is stdlib-only, but the 40 engines are driven by YAML criteria
packs. So PyYAML is a *compile-time* dependency and the runtime reads compiled
JSON — and the test blocks the import to prove it:

```python
sys.meta_path.insert(0, YamlBlocker())          # ImportError on `import yaml`
from rig_lattice.deviator.auditor import audit_all
r = audit_all("mechanism because threshold gate", llm_enabled=False)
assert r["engines"] and all("sigma" in v for v in r["engines"].values())
→ OK 44          # all 44 packs scored, RIG-L composite computed
```

## Why the cell contracts are trustworthy

The 588 contracts were generated by the vendored generator rather than copied
(iCloud hydration ran ~9 s/file, projecting to ~79 minutes). That is only
acceptable because the equivalence was measured, not assumed:

```
61 of 61 fully-hydrated originals   byte-identical to generated output
588 of 588 shipped contracts        byte-identical to a fresh regeneration
```

The two files that differed were zero-byte truncations from a killed copy —
inspected before overwriting, not waved through. `PROVENANCE.md` records it.

## Why it is not four repos in a trench coat

The RIG delta: the same 588-cell doctrine existed in four diverging
implementations — one of them iCloud-only, one a deleted private repo — with
two different Y-axis dialects, two different accept-threshold sets, and a
`route_bms` that disagreed with `BMSMode.from_score`. Fusing them meant
choosing one dialect per axis and **deleting** the losers rather than aliasing
them: `LEGACY_DIAMOND_LABELS` survives as a docstringed lookup, never an enum.
Where a vendored path could not work it now raises — `archetype_runner("A3")`
refuses instead of running the A1 code and labelling the result A3.
