# Build-time values in Next.js (App Studio sub prompt, v1)

Contract
- id: app-sub-next-build-time | version: 1 | tier: sub | parent: app-studio-web-frontend | stage: web-frontend | audience: builder
- inputs: the changed file or variable
- output: a web-frontend record row showing rebuild, restart and a fetch of the new value
- lessons carried (each one is an instruction to follow):
  - LA-09: After adding a file under public/ to a production-served Next app, rebuild and restart (next start serves only files present at build time) and fetch the new URL.
  - LA-11: Confirm every changed bundled asset URL is content-hashed and that the served URL changed, because an immutable cache on an unhashed URL keeps returning visitors on the old file.
  - LA-14: After any env change, redeploy without build cache and confirm the new value is in effect on the served build.
- gates: library gate app.prompt on this text; output gate app.stage-gate on the web-frontend record (a required noul passes only above 0.9; DEFERRED when the classifier is down, never a guessed verdict)
- done_when: after the change, `npm run build` exits 0, the server restarts, and a curl of the new file or page shows the new content
- stop: report BLOCKED: <value> when a NEXT_PUBLIC value would expose a secret; secrets never get the NEXT_PUBLIC prefix; deploy, git push, publish, purchase, emails to real people and paid API calls stay held for Mike's Gate-D approval

1. next start serves only public/ files present at build time: after adding one, rebuild, restart and fetch its URL (LA-09).
2. NEXT_PUBLIC_ values are inlined at build: change, rebuild, restart, then check the served HTML or bundle for the new value.
3. On a hosted deploy, an env change needs a redeploy without build cache (LA-14).
4. Changed bundled assets must get a new content-hashed URL (LA-11).

Evidence rule: a step counts as done only when its record shows the exact command, the exit code, and the observed output (status code, body excerpt, file hash or screenshot path). A plan, a stub, a description of the code or a green preview is not evidence.
