# Acceptance criteria

These requirements are not a statement that live execution passed. Preserve real evidence for each applicable gate; synthetic tests establish only their named test behavior.

w01. A clean installation resolves every linked family dependency without private host paths or credentials.
w02. Julie W2 priorities and current candidate constraints guide admission; missing constraints remain explicit.
w03. Every target has a complete current active official posting, canonical identity, capture time, and JD hash.
w04. Every posting has all thirteen persona sections, complete requirement coverage, and real JEV review.
w05. Employer initiatives have source URLs, dates, employer identity, relevance, and labeled inference.
w06. Company activity never becomes personal contribution without actual factual participation confirmation.
w07. Inclusion permission is recorded separately from factual participation; neither authorizes submission.
w08. All substantive requirements map to supported achievements, adjacent experience, or explicit gaps; metrics retain their evidence and scope.
w09. The original DOCX remains immutable; paragraph/run and page evidence support template fidelity for the tailored copy.
w10. Red proposals carry exact claim-bound UNCONFIRMED context; unsupported content never appears in clean final files.
w11. A tailored cover letter has the same fact boundaries, independent content review, page inspection, and hash binding as the resume.
w12. SlopMonster improves natural writing without altering ownership, metrics, facts, or uncertainty; all final documents remain ATS readable and visually intact.
w13. Genuine typed JEV receipts bind current artifacts; missing, malformed, stale, unknown, and contradictory results hold the transition.
w14. Airtable uses the named base/table/view, verified schema mapping, full-table dedupe, single-writer updates, and write readback; unknown writes reconcile.
w15. Stable application identity, bounded daily execution, current separate application approval, and unique real ATS receipts survive retries/restarts without duplicate application or false totals.

## Required adversarial cases

Test corporate initiative without participation; wording approval without factual confirmation; confirmed participation with inclusion declined; alias/manual/daily duplicate discovery; lost dispatch acknowledgment; submit timeout; Airtable field type change; accepted Airtable write with response lost and record hidden by view; malformed or stale JEV result; matching DOCX style hashes with orphaned pages and an unsupported cover-letter metric. Every case must assert its observable hold, preserved evidence, or correct dedupe result. Local fixtures do not certify provider authenticity, visual quality, GrokBot import, or live Temporal behavior.

## Core resume quality criteria stay unchanged

The w01-w15 criteria above describe this package and workflow. They do not rename or replace the inherited resume quality criteria. Core c01-c15 remain active posting identity; complete JD and duties; visible qualification gaps; requirement-to-example coverage; employer/title/date attribution; result/personal contribution/strategy; defensible metrics with units/period/attribution; focused evidence questions; fitted executive summary; concise natural honest language; ATS-readable structure/keywords; alignment/whitespace; font/headings; unclipped pagination; and exact artifact/source/review binding with human approval.

The actual quality receipt must cover core c01-c15 and bind current final pages, resume, cover letter where reviewed, sources and decisions. Preserve the inherited [quality definitions](../../job-applier/references/quality-gates.md). Never pass w01-w15 identifiers to a validator expecting core c01-c15.
