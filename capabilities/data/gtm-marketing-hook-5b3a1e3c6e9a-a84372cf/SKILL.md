# Define Customer Identity and Problem Framing Precisely

Use when: Create problem-aware messaging variants

Inputs: workspace brief, approved claims, supporting evidence

1. Draft initial customer persona and problem statement.
2. Review language for subjectivity, bias, or unnecessary adjectives (e.g., 'sexy').
3. Replace vague or offensive terms with precise functional descriptions (e.g., 'entrepreneurs', 'over consumption').
4. Map the customer's specific capability (e.g., design/funnel) against the problem.

Output contract:

- A refined customer profile and problem statement free of subjective or offensive terminology.

Limitations:

- Over-sanitizing language might remove emotional hooks if not replaced with strong functional benefits.
- Requires careful balance between precision and relatability.
