# Server-rendered first paint (App Studio sub prompt, v2)

Contract
- id: app-sub-ssr-first-paint | version: 2 | tier: sub | parent: app-studio-web-frontend | stage: web-frontend | audience: builder
- inputs: spec.md app name, {{CONTRACT}} page lines
- output: pages whose server HTML contains the app name in <title> and h1 plus the page's primary content
- lessons carried (each one is an instruction to follow):
  - TG-14: Keep / (and every public page) in the auth middleware's public-route list; a deployed landing page that demands sign-in is a shipped bug. (TubeGuruji videos: zjwj21wzs4U)
  - BENCH-02: Server-render the app name and primary content of every contract page so a raw GET without JavaScript proves the page. (evidence: a working app failed its home-page check on 2026-09-28 because the raw HTML lacked the expected text (run 6415a483, P1))
  - LA-36: Reproduce a hydration mismatch on first load and after client navigation, then fix the diverging value at its source (a mounted gate, skipHydration with an explicit rehydrate, one shared formatter, or a client-only import); suppressHydrationWarning is allowed only on the one element whose value the server cannot know (the theme attribute), never to hide a data mismatch.
  - LA-44: Import every module for the runtime that executes it: no window or document in React Native, client hooks only in files marked 'use client', env read the way the bundler exposes it, and check which surface a component is imported from before fixing an undefined-component error.
- gates: library gate app.prompt on this text; output gate app.stage-gate on the web-frontend record (a required noul passes only above 0.9; DEFERRED when the classifier is down, never a guessed verdict)
- done_when: for each page, `curl -s http://127.0.0.1:<port><path> | grep -c '<app name>'` prints at least 1 against the production server
- stop: report BLOCKED: <route> when a page can only render client-side because of a missing dependency; deploy, git push, publish, purchase, emails to real people and paid API calls stay held for Mike's Gate-D approval

1. Keep each page a server component that renders the app name (from spec.md) in <title> and an h1, plus its primary content or empty state.
2. Put interactive widgets in client components below that server shell.
3. Fetch initial data on the server so the first HTML is meaningful without JavaScript. A raw GET without JavaScript failed a working app on 2026-09-28 (BENCH-02).
4. / stays public (TG-14).
5. Fix a hydration mismatch where the value diverges: reproduce it on first load and after client navigation, then use a mounted gate, skipHydration with an explicit rehydrate, one shared formatter, or a client-only import; suppressHydrationWarning only on the theme attribute (LA-36; creators CH-CWA-01, CH-SSG-02).
6. Client hooks (usePathname, useRouter, useSearchParams) live only in files marked 'use client' (LA-44; CH-CWA-08).

Evidence rule: a step counts as done only when its record shows the exact command, the exit code, and the observed output (status code, body excerpt, file hash or screenshot path). A plan, a stub, a description of the code or a green preview is not evidence.
