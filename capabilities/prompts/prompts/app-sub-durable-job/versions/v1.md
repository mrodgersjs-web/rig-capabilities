# Durable multi-step job (App Studio sub prompt, v1)

Contract
- id: app-sub-durable-job | version: 1 | tier: sub | parent: app-studio-backend-data | stage: backend-data | audience: builder
- inputs: {{FEATURES}}, {{STACK}}
- output: a job record with ordered steps and statuses, a start endpoint that returns immediately, and a status endpoint the UI polls
- lessons carried (each one is an instruction to follow):
  - LA-05: Sweep every consumer of the transformed keys in the same change and prove background endpoints with a forced-due fixture, because a clean exit with zero work is what a broken join looks like.
  - TG-05: Never run a long multi-step AI job in the request; run it as durable steps with a status record. (TubeGuruji videos: -h1O73T0jmo, 6niOEjus2Vg, kxM_oEMn3IM, 31-Qfr2Pc5Q)
  - TG-25: Render per-step progress for every pipeline from the job's own status record. (TubeGuruji videos: ciXiibK7Gds, kxM_oEMn3IM, 6niOEjus2Vg)
- gates: library gate app.prompt on this text; output gate app.stage-gate on the backend-data record (a required noul passes only above 0.9; DEFERRED when the classifier is down, never a guessed verdict)
- done_when: the start endpoint answers in under a second, the status endpoint shows each step moving to done, and a forced-due fixture proves a scheduled step runs
- stop: report BLOCKED: job runner when the named runner (Inngest, Trigger.dev) needs keys; build the local step runner with the same shape instead; deploy, git push, publish, purchase, emails to real people and paid API calls stay held for Mike's Gate-D approval

1. Never run the long work inside the request (TG-05). Start returns a job id at once.
2. Store steps with status (pending, running, done, failed) and retry each step idempotently.
3. Render per-step progress from the job's own status record (TG-25).
4. Without runner keys, implement a local runner with the same step shape and name it the fallback.
5. Prove scheduled or background steps with a forced-due fixture; a clean exit that did zero work is a broken join (LA-05).

Evidence rule: a step counts as done only when its record shows the exact command, the exit code, and the observed output (status code, body excerpt, file hash or screenshot path). A plan, a stub, a description of the code or a green preview is not evidence.
