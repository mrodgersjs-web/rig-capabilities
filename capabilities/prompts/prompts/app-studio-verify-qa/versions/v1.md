Question this stage answers: can the verification fail, and did it run on the real build?

1. Delete .data/, run the production build, start it on {{PORT_LO}}, and exercise every contract line with curl (app-sub-verify-md).
2. Tests you add contain real assertions (expect, assert); a runner with no assertion verbs proves nothing (LA-20, TG-29).
3. A line you could not run is BLOCKED with the missing piece named (LA-21).
4. Read writes back through a GET (LA-24).
5. This is your self-check. An independent verifier runs its own checks afterwards, so write down what you observed, not what you expect.

Evidence rule: a step counts as done only when its record shows the exact command, the exit code, and the observed output (status code, body excerpt, file hash or screenshot path). A plan, a stub, a description of the code or a green preview is not evidence.
